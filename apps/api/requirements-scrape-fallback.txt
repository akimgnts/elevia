# Optional, isolated dependency for the Business France ScrapeGraphAI fallback.
#
# Installed in its OWN virtualenv (/opt/scrape-fallback-venv, see Dockerfile) —
# never merged into requirements.txt. Verified via:
#   pip install --dry-run -r requirements.txt scrapegraphai
# which forces major upgrades of fastapi, pydantic, httpx, openai, pypdf and
# python-multipart to satisfy scrapegraphai's transitive floor pins
# (langchain>=1.2.0, pydantic>=2.12.5, ...). That risk stays out of the main
# API process entirely by keeping this in its own venv.
#
# Runner: apps/api/scripts/scrapegraph_bf_runner.py
# Caller: apps/api/src/api/utils/business_france_scrape_fallback.py (subprocess only)
#
# Pin below works around an upstream scrapegraphai packaging bug: its own
# `langchain-community>=0.4.0` floor (no ceiling) lets pip resolve 0.4.2,
# which removed `ChatOllama` from `langchain_community.chat_models` — a name
# scrapegraphai's own node modules (html_analyzer_node.py, generate_answer_node.py,
# etc.) still import unconditionally at module load time, even though we only
# use the OpenAI path. Confirmed: 0.4.1 still has ChatOllama, 0.4.2 does not.
# Without this pin, `from scrapegraphai.graphs import SmartScraperGraph` raises
# ImportError before any scraping is attempted (observed in production,
# 2026-09-02: "cannot import name 'ChatOllama' from 'langchain_community.chat_models'").
scrapegraphai>=1.76.0
langchain-community<0.4.2
